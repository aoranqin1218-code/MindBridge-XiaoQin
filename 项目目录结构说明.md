# MindBridge 项目目录结构说明

> 项目路径：`F:\Agent开发\MindBridge\Project\mindbridge-py`
> 用途：学习时快速判断“某个目录负责什么、里面有哪些重要文件、应该在哪个阶段阅读”。
> 核对日期：2026-08-10。目录来自当前本地项目；未读取 `.env` 内容，也未展开 `.venv`、Chroma 二进制索引和临时验证环境的内部依赖文件。

## 1. 先看项目全貌

```text
mindbridge-py/
├── .github/       # GitHub Actions 持续集成配置
├── .venv/         # 本机 Python 虚拟环境（生成目录）
├── app/           # 后端应用源码，学习主线
├── data/          # Chroma、快照、Excel 等运行数据
├── doc/           # 分阶段学习知识卡
├── models/        # 本地 GGUF/Ollama 模型定义和模型资产位置
├── scripts/       # 启动、模型创建和发布打包脚本
├── skills/        # 运行时按需加载的标准 Agent Skills
├── target/        # 演示、测试、Harness 和兼容性验证产物
├── tests/         # 后端单元/集成回归测试
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
├── README.md
├── MindBridge项目学习总路线.md
└── AGENTS.md
```

最先建立的边界：

- `app/` 是产品代码。
- `skills/`、`app/knowledge/` 是运行时按需加载的内容资源。
- `tests/`、`app/harness/`、`app/rag_eval/` 是验证代码。
- `data/` 是持久化运行数据，`target/` 是测试/演示输出。
- `.venv/` 是依赖环境，不是业务代码。
- `doc/` 是学习资料，不参与程序运行。

## 3. `app/`：后端应用源码

`app/` 是学习和面试的主目录。它既包含 HTTP 层，也包含 Agent Runtime、业务服务、数据库实体和验证工具。

### `app/main.py`

FastAPI 应用装配根（composition root）：

- `create_app()` 创建 FastAPI 应用。
- `lifespan` 在启动时创建缺失表、初始化默认账号/知识、启动工具队列 Worker；关闭时停止 Worker。
- 注册全局中间件。
- `include_router(router)` 接入 API。
- `mount("/", StaticFiles(...))` 提供静态页面。

它负责接线和生命周期，不实现聊天、风险判断或 Agent 协作。

### `app/agents/`：Agent Runtime、协作协议与单轮 Harness

| 文件                        | 主要内容                                                                                                      | 阶段                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `harness.py`              | `MindBridgeAgentHarness`；单轮输入脱敏、Session、Runtime 调用、消息/报告/Trace 持久化和工具计划             | 阶段 1 初识，阶段 2 深入  |
| `result.py`               | `AgentStep`、`AgentRunResult`；Runtime 对外统一返回合同                                                   | 阶段 2                    |
| `events.py`               | Task、Claim、Message、Artifact、Event、`CollaborationBlackboard` 等黑板数据结构                             | 阶段 3                    |
| `registry.py`             | Agent 能力、Profile、候选选择与注册表                                                                         | 阶段 3                    |
| `autonomous.py`           | `UnderstandingAgent`、`SafetyAgent`、`ContextAgent`、`ResponseAgent`、`CoordinatorAgent` 的行为实现 | 阶段 3～5                 |
| `coordinator.py`          | `EventDrivenCoordinator`；有界调度、任务 Claim、产物审查和最终采纳                                          | 阶段 3                    |
| `event_driven_runtime.py` | `EventDrivenAgentRuntimeService`；创建服务和黑板，运行 Coordinator，转换为 `AgentRunResult`               | 阶段 3                    |
| `factory.py`              | `create_agent_runtime()`；当前固定创建事件驱动 Runtime，并报告框架状态                                      | 阶段 1 只确认实际 Runtime |
| `__init__.py`             | 把目录标记为 Python 包                                                                                        | 无需专门学习              |

注意：当前是有界、受控、Claim-based 的事件驱动多 Agent，不是无限 ReAct 循环；Agent 主要在同一进程中顺序执行，不代表并行计算。

### `app/api/`：HTTP 接口层

| 文件            | 主要内容                                                                                            | 阶段         |
| --------------- | --------------------------------------------------------------------------------------------------- | ------------ |
| `routes.py`   | 健康检查、登录用户信息、`POST /api/chat/stream`、报告/案例/Trace/工具任务管理接口、知识库管理接口 | 阶段 1       |
| `__init__.py` | Python 包标记                                                                                       | 无需专门学习 |

Route 只拥有 HTTP 边界：路径、方法、认证依赖、数据库依赖、请求 DTO、响应类型和 HTTP 错误映射；不拥有 Agent 内部业务编排。

### `app/core/`：全局基础设施

| 文件             | 主要内容                                                                   | 何时阅读                     |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------- |
| `config.py`    | `Settings`、`.env`/环境变量读取、`get_settings()` 缓存               | 阶段 0；后续排配置问题时回看 |
| `database.py`  | SQLAlchemy`Base`、`engine`、`SessionLocal`、请求级 `get_db()`      | 阶段 1 理解 DB Session       |
| `bootstrap.py` | `create_schema()` 和 `seed_data()`；创建缺失表、默认账号、同步内置知识 | 阶段 1 理解启动生命周期      |
| `security.py`  | 密码 Hash、Basic Auth 凭据解析、`current_user`、`require_admin`        | 阶段 1 跟路由依赖时阅读      |
| `enums.py`     | MessageRole、IntentType、RiskLevel、EmotionLabel、工具/案例状态枚举        | 各阶段遇到对应业务时查阅     |

`core/` 放的是多个业务模块都会依赖的基础能力，不应该包含某个 Agent 的具体 Prompt 或聊天流程。

| `memory.py`          | Redis 短期记忆、MySQL 回填所需接口、历史裁剪和摘要压缩                                                              | 阶段 5            |

关键调用方向：

```text
Route
  -> ChatService
      -> MindBridgeAgentHarness
          -> Agent Runtime
              -> Assessment / Memory / Knowledge / Skills / AI
          -> Trace / Report / Tool Plan
      -> AiClient.stream
      -> ToolQueue 或 MCP Client
```

### `app/schemas/`：API/模型消息的数据合同

| 文件            | 主要内容                                                                                             | 阶段         |
| --------------- | ---------------------------------------------------------------------------------------------------- | ------------ |
| `dtos.py`     | `ChatRequest`、`ChatStreamEvent`、知识入库请求/响应、报告/案例/工具任务/Trace DTO、`AiMessage` | 阶段 1       |
| `__init__.py` | Python 包标记                                                                                        | 无需专门学习 |

DTO（Data Transfer Object）只描述跨边界传输的数据形状和校验，不负责数据库查询和业务决策。

### `app/models/`：数据库实体

| 文件            | 主要内容                                                                                                                                                                                                                                | 阶段                  |

| `entities.py` | `UserAccount`、`ChatSession`、`ChatMessage`、`KnowledgeChunk`、`PsychologicalReport`、`RiskCase`、`CaseNote`、`AlertRecord`、`ExcelRecord`、`ToolJob`、`DeadLetterRecord`、`AgentRunTrace`、`ToolAuditRecord` | 阶段 2、5、6 按需阅读 |

```text
→ unittest 回归测试
```

它提供可重复的基础回归，但没有接入真实 MySQL、Redis、Chroma、Qwen 和 SMTP。

## 12. `.venv/`：本机 Python 虚拟环境

包含 Python 解释器、pip 和第三方依赖。它是 `pip install -r requirements.txt` 产生的环境，不是项目源码：

- 不阅读里面的 `site-packages` 来理解 MindBridge。
- 不手工修改依赖源码。
- 环境损坏时可按依赖清单重建。
- Docker 运行不使用宿主机 `.venv`。

## 13. 生成目录和缓存

- `__pycache__/`、`*.pyc`：Python 字节码缓存，可重新生成。
- Chroma 的 `.bin`、`chroma.sqlite3`：向量索引内部文件，不直接编辑。
- SQLite、Excel、日志、Harness JSON：运行或验证产物，不是源代码。
- `.env`：敏感配置，不应输出到聊天、文档、Git 或发布包。

## 16. 面试时如何概括目录设计

> MindBridge 以 `app/main.py` 作为 FastAPI 装配入口，`api` 和 `schemas` 管协议边界，`agents` 管单轮 Harness 与事件驱动多 Agent Runtime，`services` 提供 AI、风险、记忆、RAG、Skill、Trace 和工具能力，`models` 管数据库实体；`skills` 与 `knowledge` 是运行时按需加载的内容资源，`tests`、Engineering Harness 和 RAG Eval 形成验证体系，`data` 与 `target` 分别保存运行数据和测试/演示产物。
